# Архитектура Meal frontend

Клиент постепенно приводится к практичной FSD-подобной структуре по доменным моделям. Референс `staff_management_frontend` используется только как пример доменной группировки; его React Router/Vite-подходы и нарушения границ сюда не переносятся.

## Слои и направление зависимостей

```text
app → widgets → features → entities → shared
```

- `front/src/app` — только Next App Router: routes, layouts, metadata, loading/error boundaries и composition root.
- `front/src/widgets` — крупные блоки, которые компонуют несколько доменов: authenticated/public shell, навигация, общие панели состояния.
- `front/src/features/<domain>` — пользовательские сценарии конкретного домена. По мере миграции код делится на реально необходимые `api`, `model`, `lib`, `ui`, а наружу публикуется через `index.ts`.
- `front/src/entities` — только устойчивые модели, используемые несколькими сценариями. Не нужно создавать entity для каждого DTO.
- `front/src/shared` — transport, технический runtime, config, общие утилиты и UI без бизнес-знаний.

Разрешённые зависимости направлены только вправо. Нижний слой не импортирует верхний. `app` является composition root и связывает runtime с auth/offline интеграциями. Междоменный импорт допускается только через публичный API домена; чужие page-файлы, CSS Modules и внутренние сегменты не являются API.

## Next.js и публичные API

- `page.tsx`, `layout.tsx`, `loading.tsx`, `error.tsx`, route handlers и metadata остаются в `app`.
- Server Components не импортируют browser-only barrel. Если домен имеет серверные экспорты, для них создаётся отдельный `server.ts`.
- `'use client'` ставится на минимальной границе. Общий barrel не должен случайно переводить серверный код в клиентский bundle.
- Generated API contracts остаются единым generated artifact и вручную не редактируются.
- Query keys, storage keys, IndexedDB names, BroadcastChannel names и URL worker-ов считаются совместимыми runtime-контрактами.

### Route groups и release budget

Route group не является URL-сегментом. Он применяется только для доказанно идентичных nested layouts; единственный root layout остаётся `app/layout.tsx`, поэтому группы не создают переходов между разными root layouts и полных перезагрузок.

- `(personal-shell)` объединяет прежние layouts `ai`, `diary`, `finance`, `support`.
- `family/(personal-shell)` объединяет `notes` и `ownership`.
- `(shopping-workflows)` объединяет personal `shopping`, `purchases`, `receipts` с прежними `allowOffline`, `scope="personal"` и shopping shell class.
- `family/(shopping-workflows)` объединяет семейные `shopping`, `purchases`, `receipts` с прежним `scope="family"` без offline-расширения.

Все page-файлы и lazy route chunks остаются раздельными, URL не содержат имён групп. Production build должен сохранять полный набор page client-reference manifests.

Route-matrix и design-route audit строятся из `front/src/app` через один canonical discovery policy: route-group и parallel-slot segments не входят в URL, duplicate patterns запрещены, а неизвестный dynamic placeholder fail closed. Зафиксированы 119 page routes: 111 non-dev/non-moderation, 2 development-only и 6 moderation. Dynamic legal catalog route материализуется разрешённым slug `personal-data-consent`; progress design-аудита сохраняет только результаты текущего canonical pattern set. `/legal` и `/legal/[slug]` остаются публичными draft routes, а не новым authenticated product flow.

Browser budget измеряет не только число файлов. Измеренный baseline после F1 — 188 JS-файлов и 154 уникальных SHA-256 payloads; caps 196/170 дают малый headroom, но не допускают возврата прежней фрагментации. Неизменные caps остаются 900 КБ raw/140 КБ gzip на файл и 3,8 МБ raw/1 МБ gzip суммарно. Для каждого app page вычисляется union `build-manifest.rootMainFiles` и chunk paths его Next client-reference manifest; должны присутствовать manifests всех путей из `app-paths-manifest`. Route caps: не более 28 JS requests и 390 000 gzip bytes. Текущий максимум — 24 requests и 378 440 gzip bytes.

## Этапы миграции

1. Убрать зависимости доменов от `app` и инфраструктурные циклы.
2. Перенести shell-композиции в `widgets`, оставив визуальное поведение без изменений.
3. Добавлять public API и внутренние сегменты сначала низкосвязанным доменам.
4. Последовательно мигрировать bounded contexts: account/session, family, inventory, shopping, recipes, planning/subscription/AI, public/operations.
5. Только после стабилизации границ декомпозировать крупные файлы.

## Зафиксированные границы

- `entities/session/model.ts` владеет точными current-session и session-list query keys и единственной записью user-session в cache. `sessionQueryKey` сохраняет singular `['session', user|staff]`, а `sessionListQueryKey` — намеренно отдельный plural `['sessions', user|staff]`; staff/moderator mapping, Staff MFA success и moderator 401 recovery не изменены. Приватный auth `sessions-api.ts` выполняет explicit user/staff list/logout/revoke dispatch, а `sign-in-api.ts` — explicit password/TOTP/PIN и staff challenge/MFA dispatch; оба сохраняют caller AbortSignal, exact response projections и native errors. WebPush cleanup, runtime reset/broadcast, MFA challenge/recovery-code lifecycle, cache writes, error mapping и redirect остаются UI-owned. Dev-only mailbox использует отдельный узкий `mock-mailbox-api.ts`, не расширяя production route boundary.
- `entities/session/client.ts` владеет browser-hook `useSession`; feature-домены больше не импортируют session model из `features/auth`.
- Offline owner и очистка recipe cache остаются feature-эффектами, подключёнными к session entity через порт composition root в `app/providers.tsx`.
- `entities/workspace-scope/model.ts` владеет выбранным personal/family workspace и его привязкой к текущему user id; технический `shared/runtime` больше не хранит бизнес-состояние scope.
- `entities/workspace-scope/client.tsx` предоставляет изолированный provider/hook, а `app/providers.tsx` атомарно сбрасывает scope вместе с session cache при logout, смене аккаунта и BroadcastChannel-событии.
- Только auth/session boundary и явные family create/join/leave-команды меняют workspace scope. Доменные page-shell больше не конкурируют за него эффектами; UI scope `personal|family` не смешивается с API scope `private|family`.
- `entities/family/model.ts` владеет canonical query keys `['family']` и `['family', userId]`, типами family context и стабильной account-scoped моделью. `entities/family/client.ts` является единственной точкой canonical family query; отдельный meal-plan key `['family-context', userId]` намеренно не объединён.
- `features/family/query-keys.ts` владеет приватными family workflow projections для invitations, invitation preview, leave preview, ownership overview/request и ownership notice. Exact account/version/token tuples, broad ownership prefix и leave-preview account prefix сохраняют query/remove/set/invalidate semantics; cross-domain notification invalidation использует notification entity root. Приватный `features/family/api.ts` владеет family context/setup, invitation/member/leave и ownership/notice reads и commands с explicit action dispatch. Adapter сохраняет signals, token/path/query params, `.data`/envelope projections и caller-prepared version/idempotency bodies; role gates, persistent `ExactAttempt`/useRef retry, unknown-outcome readback, session/workspace, cache/notification fan-out и router остаются UI-owned.
- `entities/notification/model.ts` публикует server-safe canonical notification query keys: broad root, account prefix, category/unread list, preferences и WebPush config. Private `features/notifications/api.ts` владеет typed center/preferences reads и read/read-all/preferences commands с exact filters, signals, params, expectedVersion, fresh UUID и native error/data semantics. URL filters, on-settled cache refresh, BroadcastChannel, preference drafts/recovery и Web Push browser permission/subscription lifecycle остаются UI-owned; family ownership notice использует canonical broad root.
- Server Components импортируют shell-классы только через server-safe `features/<domain>/server.ts`. Внутренние `shell-styles.ts` и client-only feature-файлы не являются API слоя `app`.
- Client-only межслойные экспорты feature публикуются отдельным `client.ts`; например, `OwnershipNotice` не импортируется widget напрямую из внутреннего файла family feature.
- `widgets/session-guard` компонует session entity, family/workspace scope и offline policy. Auth redirect, loader и fail-closed error живут только здесь; feature-компоненты не охраняют маршруты самостоятельно.
- Доступ к защищённым экранам задаётся только в `app` через `SessionGuard`, `PersonalShell` или `GuardedUserAppShell`. Offline разрешение объявляется на route boundary и не может расширяться внутренним feature.
- Публичные `/recipes/[id]` и `/authors/[username]/**`, а также pre-session `/moderation/sign-in` и `/moderation/mfa` намеренно не получают session guard.
- `shared/api/use-request-signal.ts` владеет технической отменой transport-запросов при повторном действии и unmount; auth feature не является источником общих инфраструктурных hooks.
- `entities/consent/client.ts` владеет account-scoped legal-consent query и распознаванием согласованных consent-required error codes. AI, diary, nutrition, notifications, personalization и recipes не импортируют внутреннее состояние legal feature.
- `entities/offline` владеет стабильными IndexedDB store/queue/snapshot контрактами и browser owner state; UI настроек и sync coordinator остаются в offline feature.
- `entities/recipe-cache/model.ts` владеет read-only recipe cache и неизменным storage key. Offline runtime зависит только от этой entity, поэтому циклическая связь `recipes ↔ offline` запрещена.
- `entities/recipe/model.ts` владеет стабильными wire-code справочниками единиц, категорий и методов, а `entities/recipe/client.tsx` — общим recipe image/rating presentation без feature-зависимостей.
- Private recipes `read-api.ts` владеет bounded catalog, public/community, prepared и family read projections, а reminder preferences изолированы в `cooking-reminders-api.ts`; recipe/author recommendation reads остаются в canonical `entities/recommendation` и публикуются через client entrypoint. Filters, pagination, signals, response projections, query/cache lifecycle, recommendation actions и paired commands остаются UI-owned.
- Private recipes `cooking-read-api.ts` владеет cooking list/detail, stock/location projections и public-first recipe read с 404-only workspace fallback. Offline snapshot selection/save, polling, stock choice composition, lifecycle commands, persistent UUID, unknown-outcome recovery и cache fan-out остаются в cooking UI; отсутствие scope/localDate в locations request сохранено намеренно.
- Private recipes `detail-api.ts` владеет public/personal/statistics reads и bookmark transport. Bookmark adapter принимает caller-owned persistent idempotency body и AbortSignal; URL servings, initial/stale/enabled query state, abort handling, 401 session reset, rating, cache invalidation и error recovery остаются в detail UI.
- Private recipes `editor-api.ts` владеет editor product/workspace reads и explicit create/update transport dispatch. Adapter принимает caller-owned body, persistent UUID, expectedVersion и AbortSignal; отсутствие If-Match сохранено. Validation/fingerprint, offline queue/snapshots/draft state, unknown outcome/conflict, router и cache fan-out остаются в editor UI.
- Публичный recipe feed, comments и `/community` являются сценариями recipes bounded context и публикуются через `features/recipes/client.ts`; бывший цикл `recipes ↔ community` удалён.
- Read-only recipe report history/detail transport изолирован в приватном `features/recipes/reports-api.ts`: page/limit, path id, caller AbortSignal, exact data projection и native errors сохранены. Query lifecycle, account-scoped keys, pagination links, loading/error recovery и скрытый recipe fallback остаются в `reports.tsx`; это первый bounded transport checkpoint recipes, остальные cooking/editor/community lifecycles не смешиваются с ним.
- Приватный `features/recipes/read-api.ts` владеет отдельными read-функциями public feed/comments, prepared stock options и family recipe/products: normalized filters, conditional cursor/category/author, limits 12/20/100, family scope, path ids, caller AbortSignal и exact projections сохранены. Infinite-query lifecycle, batch filtering, product lookup, edit affordance и все commands/cache effects остаются в UI; эти разные payloads не объединены в один cache contract.
- Приватные `features/recipes/mine-api.ts` и `allergens-api.ts` закрывают последние прямые recipe transport sites. Mine adapter сохраняет exact paged workspace filters и явный `archive|restore|submit|rollback` dispatch с caller-owned persistent UUID/version/body без `If-Match`; allergens adapter принимает уже зафиксированный fingerprint/UUID report body и возвращает exact ticket projection. Offline snapshots/queue, unknown-outcome recovery, consent, cache/router effects и dialog state остаются в UI.
- `entities/measurement/model.ts` владеет общими quantity unit wire-codes, `entities/inventory` — inventory scope, canonical query keys и expiry presentation, а локальная календарная дата остаётся чистой утилитой `shared/lib/date.ts`. Broad inventory invalidation в diary, inventory create/detail и cooking использует единый `inventoryKeys.root`; factory-compatible list/batch/location/cooking-review projections, locations, attention, history и inventory product-search caches используют exact entity factories и roots. Private `features/inventory/api.ts` владеет typed product/location/list/batch/history reads и batch/location commands, сохраняя scope/localDate/search/pagination, signals, projections и conditional `If-Match`; caller-prepared UUID/version bodies, unknown-outcome/conflict recovery, drafts, dialogs, routing и cache fan-out остаются UI-owned. Preserves locations `[userId, scope]` и cooking locations `[userId]` также получили явных entity owners, но намеренно остаются отдельными full-response projections: canonical `locations(scope, userId)` кэширует только `items`. Их будущее объединение требует подтверждённого backend default scope и согласованной миграции cached result shape. Dynamic multi-root history loops в preserves/shopping сохраняют текущие формы до отдельной миграции.
- Products не импортирует inventory feature: async-state и CSS локальны, pure inventory/measurement модели берутся из entities, а routes входят только через `features/products/client.ts`. Private `features/products/api.ts` владеет typed reference/detail и product-scoped inventory/location reads, сохраняя signals, params, exact queries и result projections. Proposal adapter принимает уже подготовленные UI body/idempotency key и AbortSignal без генерации или замены; fingerprint, persistent unknown-outcome retry, abort guards и cache/router effects остаются UI-owned. Private product locations и inventory screens используют один cache key и explicit `scope=private`.
- Inventory ingest сохраняет собственные preview/review/commit UI и worker, но scope, routes, query keys, units и command errors берёт только из entities/shared. Приватный typed adapter владеет review catalog/location reads и import commit: barcode/q discriminator, scope query, AbortSignal и data projections сохраняются; уже сформированный pending command передаётся по ссылке без замены UUID, поэтому unknown-outcome retry остаётся тем же запросом. Multipart FormData preview/scan uploads и их AbortController lifecycle остаются в соответствующих UI. Sibling-feature зависимостей нет; routes входят через `features/inventory-ingest/client.ts`, а no-op shell не дублирует app layout. Catalog и locations cache привязаны к user/scope; UI не предлагает commit без обязательного `locationId`.
- Receipts являются сценариями shopping/purchase bounded context и хранятся в `features/shopping/receipts`; purchase review/resolution, command runtime и CSS теперь внутри одного feature, а receipt routes входят через `features/shopping/client.ts`. Приватный `features/shopping/api.ts` владеет list/detail/history/recipe, catalog/location/purchase и receipt capability/detail/duplicate reads вместе с тремя preview commands, сохраняя prepared query/body identity, signals, params и `.data`/`.items` projections. Offline snapshots, product visibility, persistent UUID/unknown-outcome command runtime, OCR/upload и PDF fail-closed, drafts, cache fan-out и router остаются UI-owned.
- `shared/media/image-validation.ts` владеет единой pre-decode проверкой JPEG/PNG/WebP, animation и 20 MP limit для receipt и inventory ingest; media security больше не зависит от feature.
- Shopping list routes используют только `features/shopping/client.ts`; legacy re-export через recipes удалён, поэтому recipes больше не зависит от shopping feature.
- `entities/finance-cost` владеет общей account-scoped моделью примерной стоимости рецепта, списка покупок и плана питания: `query-keys.ts` фиксирует exact route/resource/user tuple, `api.ts` явно dispatch-ит три generated GET operation, а `client.tsx` сохраняет публичный badge API. Meal plan, recipes и shopping не импортируют finance page internals.
- Preserves получает единицы измерения из `entities/measurement`, а локальную календарную дату — из `shared/lib/date`; inventory feature не является библиотекой соседнего домена.
- Finance и meal-plan routes входят через `features/finance/client.ts` и `features/meal-plan/client.ts`.
- `features/finance/query-keys.ts` владеет distinct analytics, prices/catalog, expense list/detail и overview/budget projections, а `features/finance/api.ts` — typed reads и price/expense/budget commands. Adapter сохраняет date/category omission, signals/path params, `.data`, caller-prepared bodies/versions и If-Match/native errors; consent/form validation, fresh UUID, POST/PUT selection, drafts/stale recovery и finance/Pro cache fan-out остаются UI-owned.
- `entities/recommendation` владеет общей моделью recommendation actions, feedback и follow-команд. `query-keys.ts` фиксирует exact recipe/author projections вместе с broad `['profile-following']` prefix, account-scoped list tuple и author-follow state tuple. Home сохраняет cache scope `personal|family`, хотя transport переводит personal в private; recipes сохраняет private/12 и author/3 tuples. Приватный typed adapter обслуживает following pagination, author follow state, feedback events и follow command; generated bodies/params, fresh UUID per invocation, void/data projections и error identity сохранены, а impression-дедупликация и cache side effects остаются в entity client.
- `entities/profile` владеет canonical profile projections: `query-keys.ts` фиксирует exact own/public/public-achievements/public-reputation tuples, а typed adapter сохраняет generated GET operations и PUT собственного профиля, path params, AbortSignal, exact body/data projection и fresh idempotency key. Achievements/public-progress, profile pages, account-security и recommendation self-check используют entity owners; mutation lifecycle, draft, theme/session/cache side effects и recovery остаются в profiles feature. После F2BP direct transport context `profiles` закрыт.
- `entities/pro-overview` владеет account-scoped Pro overview read model и broad invalidation root: typed adapter сохраняет generated GET, AbortSignal и data/error semantics, а diary, finance и nutrition mutations инвалидируют canonical prefix без переноса command bodies, optimistic versions или idempotency ownership.
- Profile feature владеет загрузкой, редактированием и presentation профиля, но получает following, follow action, public progress и recipe feed композиционными слотами. `widgets/profile-pages` связывает эти домены через их client APIs; route-модули не импортируют внутренности profile feature.
- `widgets/account-security` компонует account security и sessions через `features/auth/client.ts`; layout CSS локален widget, а внутренние формы и `.sessions-panel` стили остаются во владении auth feature.
- `entities/account-security` владеет общей critical re-auth boundary и двумя намеренно раздельными exact query keys: settings `['account', 'security']` и open-gated critical re-auth `['auth', 'security', 'critical-reauth']`. Entity typed adapter сохраняет generated settings/password/email/PIN/authenticator/critical-reauth operations, caller AbortSignal, exact command body/data projection и исходную error identity. UI по-прежнему управляет validation/drafts, refresh ordering, authenticator enrollment expiry/recovery display, broadcast и session/WebPush termination. Cache lifecycles не объединяются, одноразовый token не хранится в глобальном состоянии, а purpose остаётся частью серверной проверки.
- CSS Modules апелляций AI и privacy принадлежат своим feature-доменам. Support и personalization больше не выступают неявными библиотеками стилей соседних сценариев.
- `features/personalization/query-keys.ts` владеет exact account-scoped tuple `['personalization', userId]`, а приватный `api.ts` — тремя generated transport operations настроек и онбординга. Оба route-screen используют внутренние owners; публичный `client.ts`, UI и wire-контракты не расширены.
- `features/news/query-keys.ts` владеет exact guest/account-isolated list/detail tuples, а приватный `api.ts` — пагинированной лентой, detail query и mark-read command с fresh idempotency key per invocation. Публичный `client.ts`, URL, UI и wire-контракты не расширены.
- `features/search/query-keys.ts` владеет exact account/type/query/limit tuple единого поиска, а приватный `api.ts` — cursor pagination и generated GET transport. Четыре параллельных result-типа, URL/debounce/reload и partial-source recovery сохраняются внутри feature без расширения публичного `client.ts`.
- `features/auth/lifecycle/query-keys.ts` владеет приватными exact projections публичного registration manifest и reset-link token, а `features/auth/lifecycle/api.ts` — typed register/resend/recovery/email-link/reset operations с caller-prepared legal evidence/token/password inputs, AbortSignal, exact data projections и native errors. Legal manifest/refetch, fail-closed registration evidence, `retry:false`, reset `gcTime:0`, one-time token/history cleanup и session/WebPush termination остаются в lifecycle UI; wire-контракты намеренно не добавляют отсутствующий idempotency key.
- `features/auth/home/query-keys.ts` владеет exact account-scoped `['home', userId]` projection агрегированной главной, а private `home/api.ts` — двумя read-only home/recommendation transport projections. Adapter сохраняет AbortSignal, exact personal→private/family query, limit 3 и recipe-only projection; loading/error UI, независимый partial recommendation recovery и recommendation actions остаются в screen/entity ownership.
- `entities/export` владеет canonical broad `['exports']` prefix, exact account-scoped history projection и lifecycle-specific account projection через server-safe `model.ts`. Exports history/post-create invalidation и account-lifecycle export gate используют один entity owner; private `features/exports/api.ts` владеет typed history/download/preview/create transport calls и сохраняет signals, cursor omission, params, response projections и native errors. Preview→critical reauth→create orchestration, polling, unknown-outcome persistent idempotency ref и Blob URL/download lifecycle остаются в UI.
- `entities/ai-balance` владеет exact account-scoped `['ai-balance', userId]` projection через server-safe `model.ts`. AI overview, balance и conversation используют единый cache owner для чтения, purchase write и post-command invalidation, а subscription инвалидирует тот же account cache после изменения тарифа; GET balance, purchase payload, UUID/expectedVersion, family/meal-plan invalidations и UI остаются в своих feature-границах.

## Контролируемый архитектурный долг

Architecture gate не использует открытые allowlist: любой cross-feature import или deep import из `app`/`widgets` немедленно ломает проверку. Route- и widget-модули могут входить в feature только через `client.ts`, `server.ts` или `index.ts`, включая узкие доменные subpath API с таким basename.

Gate строит module edges через TypeScript Compiler API: static, side-effect и type imports, named/star/type re-exports, literal `require`, import-equals и dynamic `import()` проверяются одинаково. TypeScript resolution закрывает aliases, extensionless imports и `.js`→`.ts`, а отдельный asset fallback сохраняет границы CSS Modules. Nonliteral dynamic imports в layered source запрещены, generated `.next`/`dist` не входят в source-root обход. Runtime-граф production TypeScript дополнительно обязан оставаться без strongly connected components: type-only и asset edges не создают runtime-связь, а неразрешимый локальный runtime import блокирует проверку. Regression fixtures автоматически используют соседний с репозиторием `projects/tempFiles`; опциональный `QA_OUTPUT_DIR` принимается только внутри этого корня. Fixtures подтверждают эти формы до проверки реального дерева.

Отдельный TypeScript AST ratchet фиксирует production query-key literals по стабильному fingerprint `repo-relative file | operation | normalized tuple shape` с multiplicity, без номеров строк. Начальный baseline F2A составлял 298 raw sites в 78 файлах и 33 bounded contexts; ownership-миграции F2B–F2BJ поэтапно перенесли production query keys и legacy legal factory на canonical feature/entity owners. Новые fingerprint, увеличение multiplicity, новый raw-файл/контекст и произвольный helper запрещены. Уменьшение долга требует намеренного обновления inspectable snapshot. Raw tuple разрешён напрямую либо через локальную цепочку identifier/parentheses/`as const`; hook options обязаны предоставлять статически видимый `queryKey`, а прочие computed-выражения fail closed. Canonical factories разрешены только из entity `model`/`query-keys` или из `query-keys` того же feature; mocks, tests, generated contracts, `.next` и `dist` не входят в обход.

F2BE–F2BJ переносят filtered workspace/detail, cooking reads, cross-context invalidation roots и legal settings cache key на canonical feature/entity owners. Production raw query-key baseline и legacy factory debt закрыты до 0 / 0 / 0 / 0. Pagination, offline snapshots, fallback transports, success/active/401 guards, fan-out order/default options, consent cache lifecycle и response shapes не изменены.

Отдельный transport-request AST ratchet фиксирует прямые production `ApiClient.request` вызовы в `features/**/*.tsx` и `entities/**/*.tsx` до начала поэтапного переноса transport ownership. Inspectable baseline F2BO: 241 site / 72 файла / 25 contexts, из них features 237 и entities 4; 123 read и 118 command; 233 literal и 8 явно инвентаризированных computed route sites. Fingerprint сохраняет файл, method set, read/command, literal/computed и точную нормализованную route shape с multiplicity. Локальные aliases должны происходить от canonical `api` receiver либо иметь проектный `ApiClient` type; произвольный `.request` не считается transport. Literal, conditional, local-identifier и template routes разбираются AST, а неизвестный, смешивающий read/command или не соответствующий `/api/v1` route fail closed. Tests, mocks, generated contracts, server-only modules и build output не входят в production baseline. Любой новый/increased fingerprint и любое уменьшение требуют намеренного обновления snapshot: gate не заменяет будущую bounded-context migration и не разрешает массово переносить команды без idempotency/unknown-outcome проверок.

- Feature-to-feature imports полностью устранены; baseline в `front/scripts/check-architecture.mjs` пуст и запрещает появление новой междоменной связи.
- App-to-feature deep imports полностью устранены. Шесть checkpoint убрали все 100 связей: low-coupling маршруты, news/notifications/support/moderation/offline/personalization/achievements, auth/AI/AI appeals, family/family notes, inventory/preserves/shopping и recipes. URL, runtime-семантика и wire-контракты не менялись.

- Mock inventory-ingest adapter принадлежит самому bounded context в `features/inventory-ingest/mock.ts`. Только `src/mocks` может импортировать этот узкий mock API; production-слои и остальные внутренние feature-файлы закрыты gate.
